# Meme Vault v0.3 AI 自动标签实施计划

## 目标

在现有 Meme 详情页增加一次完整且可审计的 AI 图片分析流程：

1. 用户主动发起分析。
2. 后端读取已经保存的原图，通过统一 `AIClient` 获取图片描述和带置信度的标签建议。
3. 分析结果单独保存，但不修改 Meme 描述、正式标签或 `MemeTag`。
4. 用户在前端选择建议，并决定是否采用 AI 描述。
5. 只有确认接口成功后，才把选中标签追加到 Meme，并按需保存描述。

不实现批量分析、自动后台任务、文案生成、语义搜索、向量存储或供应商切换界面。

## AI 客户端

- 定义供应商无关的 `AIClient` 协议，以及 `AIImageResult`、`AITagSuggestion` 数据结构。
- 首个适配器使用 OpenAI Responses API，并通过现有 `httpx` 发送请求，不增加 SDK 依赖。
- 原图以 Base64 data URL 作为 `input_image` 发送。
- 使用严格 `text.format` JSON Schema约束返回：
  - `description: string`
  - `tags: [{name: string, confidence: number}]`
- 配置全部来自环境变量：
  - `OPENAI_API_KEY`：必填密钥。
  - `OPENAI_MODEL`：默认 `gpt-5.6-luna`。
  - `OPENAI_BASE_URL`：默认 `https://api.openai.com/v1`。
  - `AI_TIMEOUT_SECONDS`：默认 30 秒。
- 密钥不写入日志、数据库、API 响应或 Git。

## 服务端数据模型

新增 `MemeAIAnalysis` 表：

- `id`
- `meme_id`
- `model_name`
- `description`
- `suggestions_json`
- `created_at`
- `confirmed_at`

`suggestions_json` 保存经过服务端规范化和限制后的标签名、置信度以及是否为已有标签。模型名保存在分析记录中；确认后的 AI 标签继续使用已有 `MemeTag.source="ai"` 和 `MemeTag.confidence` 字段。

新增表使用 `create_all` 创建，不修改已有表结构，不需要破坏性迁移。

## 服务端业务规则

- 分析前通过 `MemeService.get_meme()` 同时验证记录和原图存在。
- 把当前标签库名称交给 AI，明确要求优先复用已有标签。
- 服务端不信任模型输出，统一：
  - 裁剪、小写化并按名称去重。
  - 将置信度限制到 0 到 1。
  - 总建议最多 8 个。
  - 新标签最多 3 个。
- 分析阶段只写 `MemeAIAnalysis`，不创建 Tag、不建立 MemeTag、不更新 Meme 描述。
- 确认阶段：
  - 分析必须属于当前 Meme 且尚未确认。
  - 选中标签必须来自该分析的建议。
  - AI 标签采用追加语义，不删除用户原有标签。
  - 已有用户标签不会被降级为 AI 来源。
  - 新建立的 AI 关联写入对应置信度。
  - `apply_description=true` 时才保存 AI 描述。
  - 标签、描述和 `confirmed_at` 在同一事务提交。

## HTTP API

### `POST /api/memes/{meme_id}/analyze`

返回：

```json
{
  "id": 1,
  "meme_id": 12,
  "model_name": "gpt-5.6-luna",
  "description": "图片内容描述",
  "suggestions": [
    {"name": "reaction", "confidence": 0.91, "existing": true}
  ],
  "created_at": "2026-07-27T00:00:00Z",
  "confirmed_at": null
}
```

### `POST /api/memes/{meme_id}/analyses/{analysis_id}/confirm`

请求：

```json
{
  "tags": ["reaction"],
  "apply_description": true
}
```

返回更新后的 `MemeResponse`。

错误映射：

- 404：Meme 或分析不存在。
- 409：分析已经确认。
- 410：Meme 原图缺失。
- 422：确认了不属于该分析的标签。
- 502：AI 上游失败或响应无效。
- 503：未配置 API Key。
- 504：AI 请求超时。

## 前端交互

- 详情面板增加“AI 分析”按钮和独立忙碌/错误状态。
- 分析成功后显示：
  - 模型名。
  - 图片描述预览。
  - 标签复选框、置信度和“已有/新建议”标识。
  - “采用这段描述”复选框。
- 建议默认选中，但在用户点击“确认采用”前不发送确认请求。
- 确认成功后同步当前详情和网格卡片，并刷新标签筛选列表。
- 分析或确认失败时保留当前结果与勾选状态，允许重试。

## 测试

### Pytest

- AI 客户端从环境变量读取配置，构造正确的 Responses API 请求。
- 正确解析结构化响应。
- 缺少密钥、超时、HTTP 错误和无效响应映射为明确异常。
- 服务端优先标识已有标签、限制新标签、规范化和去重。
- 分析不修改 Meme、Tag 或 MemeTag。
- 确认后才追加标签并保存置信度；原用户标签来源保持不变。
- 模型名和分析结果被记录。
- 重复确认、越权标签、404、410 和上游错误状态码正确。

### Vitest

- API 客户端发送分析与确认请求并解析错误。
- 详情页展示模型、描述、置信度及已有/新建议。
- 发起分析不会提前同步正式标签。
- 用户选择后确认，网格、详情和标签筛选同步。
- 分析与确认失败保留结果并可重试。
