# Meme Vault v0.1.1 后端收尾设计

## 目标

在不开发 TypeScript 前端、不改变现有分层结构的前提下，完成图片 HTTP 访问、可迁移文件引用、缺图记录删除、关键词搜索、Pytest 临时目录配置及相关文档和测试。

## 范围约束

- 保持 API → Service → Repository/Storage 的调用链。
- 不引入数据库迁移框架，不重命名现有数据库字段。
- 不自动批量修改已有数据库记录。
- 不创建或修改 TypeScript 前端文件。
- 不进行与 v0.1.1 无关的重构。
- 静态文件服务与 `get_meme_service()` 创建的 `ImageStorage` 必须使用同一组目录。

## 方案选择

采用保留现有 `file_path`、`thumbnail_path` 字段并让新记录保存文件名的方案。

没有采用以下方案：

- 重命名字段并迁移数据库：概念更准确，但需要迁移机制，超出 v0.1.1 范围。
- 通过专用 API 动态转发图片：会增加数据库查询和 Python 文件传输开销，静态文件挂载已能满足需求。

## 文件存储与 HTTP URL

`app/config.py` 集中定义原图目录、缩略图目录以及对应的同源 URL 前缀。

`app/main.py` 提供轻量的 `create_app(images_dir, thumbnails_dir)` 应用工厂。它先创建原图和缩略图目录，再分别挂载两个 `StaticFiles`。生产环境继续使用默认目录创建全局 `app`。只暴露图片目录，不暴露包含数据库的整个 `data/` 目录。

`create_app()` 将解析后的目录保存到 `app.state.images_dir` 和 `app.state.thumbnails_dir`。`get_meme_service()` 通过当前 `Request` 读取这两个值，并用它们创建 `ImageStorage`。静态文件挂载和业务文件存储因此始终来自同一个应用状态，不允许各自使用独立默认值。

新上传的 Meme 在数据库中只保存原图文件名和缩略图文件名。`ImageStorage` 仍使用绝对 `Path` 完成实际读写，但负责把数据库文件引用解析为当前配置目录内的安全路径。

旧绝对路径不自动改库：

- 路径仍位于当前配置目录内时可直接使用。
- 提取旧引用文件名前，先把反斜杠统一替换为正斜杠，以兼容 Windows 路径迁移到其他平台。
- 路径位于当前目录外或因项目移动而失效时，只取规范化后的文件名并在当前配置目录中查找。
- 解析结果必须位于配置目录内，不能借旧路径访问或删除其他目录的文件。

API 响应删除 `file_path` 和 `thumbnail_path`，增加：

```json
{
  "image_url": "/media/images/abc.png",
  "thumbnail_url": "/media/thumbnails/abc.png"
}
```

`MemeResponse.image_url` 的类型为 `str`，`MemeResponse.thumbnail_url` 的类型为 `str | None`。缩略图引用为空时返回 `null`。

API 层只定义一个 `_to_meme_response(meme)` 转换函数，所有上传、列表、随机、详情和更新路由统一通过它将 ORM 对象映射为 `MemeResponse`，并在同一位置生成两个媒体 URL。浏览器访问不存在的媒体文件时，由静态文件服务返回 `404`。

## 关键词搜索

`GET /api/memes` 增加可选的 `q` 查询参数，并沿现有分层传递到 Repository。

搜索规则：

- 去除 `q` 两端空白；空字符串视为未搜索。
- 对 `title` 和 `description` 做不区分大小写的包含匹配。
- 标题或描述任意一个匹配即可命中。
- `q` 与 `tags` 同时出现时，两类条件都必须满足。
- 应用完搜索和标签条件后，再执行排序、分页。

## DELETE 缺图记录

DELETE 不调用会检查文件完整性的 `get_meme()`，而是直接通过 Repository 查询记录。

- 数据库记录不存在：返回 `404`。
- 数据库记录存在：先保存文件引用，删除数据库记录并提交，再以 `missing_ok=True` 清理原图和缩略图。
- 原图、缩略图或两者均缺失：仍成功删除记录并返回 `204`。
- GET 和 PATCH 的缺图行为不变，仍返回 `410`。

## 测试设计

遵循测试驱动开发，先增加失败测试，再写最小实现。

测试覆盖：

- 新上传记录的数据库字段只保存文件名。
- 新文件名和旧绝对路径均能安全解析；Windows 反斜杠路径先规范化，目录外路径按文件名回落到当前存储目录。
- `create_app()` 在挂载前创建目录，并让 `app.state`、`StaticFiles` 和 `get_meme_service()` 使用同一组目录。
- API 响应包含 `image_url`、`thumbnail_url`，且不包含本地路径字段。
- `thumbnail_url` 在无缩略图引用时为 `None`。
- 所有返回 Meme 的路由统一使用 `_to_meme_response()`。
- 原图和缩略图 URL 可通过 ASGI 客户端读取。
- 缺图记录可通过 DELETE 清理。
- `q` 匹配标题或描述，忽略大小写，空白值不筛选。
- `q` 可与标签和分页组合。
- 原有测试继续通过。

API 测试通过 `create_app()` 挂载临时图片目录，使 Service 存储位置与媒体 URL 指向同一目录。

## Pytest 配置

新增 `pytest.ini`：

```ini
[pytest]
addopts = --basetemp=.pytest_tmp
```

`.gitignore` 增加 `.pytest_tmp/`，避免临时测试文件进入版本控制。

## 验收标准

- 原图和缩略图能通过 API 返回的同源 URL 在浏览器访问。
- API 不返回服务器绝对路径。
- 新数据库记录不依赖项目绝对位置，旧路径保持安全兼容。
- 静态媒体目录与 `ImageStorage` 目录始终一致，并在挂载前存在。
- Windows 风格旧路径迁移到其他平台后仍能按文件名解析。
- `thumbnail_url` 保持 `str | None`，所有 Meme 响应由同一转换函数生成。
- 缺图 Meme 可正常删除。
- `GET /api/memes?q=...` 正确搜索标题和描述，并能组合标签与分页。
- `pytest.ini` 和 `.gitignore` 正确管理 `.pytest_tmp`。
- README、PROJECT_PLAN 与实现一致。
- 全量测试通过。
