# Meme Vault 瀑布流与原图查看器设计

## 背景

v0.2 前端将卡片缩略图和详情图片放在固定 `4 / 3` 容器中。图片元素作为 Grid 子项参与固有尺寸计算，百分比高度形成了大于父容器的图片盒，随后被 `overflow: hidden` 裁切。纵向 Meme 因而只能看到顶部区域。

后端缩略图生成逻辑使用 Pillow `thumbnail()`，保持原始宽高比；例如 `1260 × 1861` 的原图会生成 `271 × 400` 的缩略图。因此本次只修复前端布局和浏览交互，不修改后端图片处理或 API Schema。

## 目标

- 网格卡片按照图片真实长宽比完整显示，不裁切内容。
- 卡片以响应式瀑布列排列，窗口宽度变化时自动调整列数。
- 标题和标签不占用常驻卡片高度，只在鼠标悬停或键盘聚焦时覆盖显示。
- 详情面板完整显示原图，并提供全屏查看入口。
- 保持现有搜索、筛选、分页、随机和 CRUD 行为不变。

## 非目标

- 不实现触屏设备专用交互。
- 不增加拖拽、批量操作、前端路由或第三方布局依赖。
- 不增加图片缩放、旋转、下载管理或键盘翻页。
- 不修改缩略图生成尺寸、媒体路由或数据库结构。

## 瀑布流布局

资料库使用 CSS 多列布局：

- `.meme-grid` 通过 `column-width` 和 `column-gap` 根据可用宽度自动选择列数。
- `.meme-card` 使用 `position: relative`、`display: inline-block`、`width: 100%`、明确的底部间距和 `break-inside: avoid`，确保一张卡片不会跨列拆分。
- 卡片保持当前 DOM 顺序，但视觉流向为先从上到下填充一列，再进入下一列。
- 加载更多后由浏览器重新排布，不运行 JavaScript 高度测量。

原生 CSS Masonry 仍属于 CSS Grid Level 3 工作草案，不作为稳定实现基础。CSS 多列布局无需新增依赖，能够满足按列浏览和响应窗口变化的要求。

## 卡片图片与覆盖信息

- 卡片缩略图继续优先使用 `thumbnail_url`，缺失时回退到 `image_url`。
- `<img>` 写入 API 返回的 `width`、`height`，浏览器可在图片加载前预留正确比例。
- 图片使用 `display: block; width: 100%; height: auto`，不再设置固定 `aspect-ratio` 或百分比高度。
- 标题与标签作为绝对定位的底部覆盖层，使用深色渐变保证文字可读性。
- 覆盖层默认透明；在 `.meme-card:hover` 和 `.meme-card:focus-visible` 时淡入。
- 选中状态继续使用亮色描边，并与悬停覆盖层相互独立。
- 图片加载失败时显示现有占位反馈，卡片仍可被选择。

## 详情面板

- 详情图片取消固定 `4 / 3` 比例，按自然比例完整显示。
- 图片区域改为语义化按钮，支持鼠标点击和键盘激活。
- 详情面板继续使用现有内部滚动，因此纵向长图不会挤出视口，用户可继续浏览元数据、编辑和删除操作。
- 编辑状态复用同一完整图片预览，不改变表单行为。

## 全屏原图查看器

页面只挂载一个原生 `<dialog>`，选择不同 Meme 时复用：

- 点击详情图片后，将当前 Meme 的 `image_url`、标题和原始尺寸写入查看器。
- 每次打开前清除上一张图片留下的 `hidden`、`.is-broken` 和错误提示状态；若 `<dialog>` 已经打开，则只更新内容，不重复调用 `showModal()`。
- 图片放在具有明确视口宽高上限的容器中，并使用 `object-fit: contain` 适配该容器，保证整张图片同时可见。
- 查看器提供右上角关闭按钮、点击背景关闭和原生 `Escape` 关闭；背景关闭仅在 `event.target === dialog` 时触发，点击图片、标题或内部按钮不会关闭。
- “打开原图”链接使用当前 `image_url`，设置 `target="_blank"` 和 `rel="noopener noreferrer"`，在新标签页打开实际媒体文件。
- 查看器图片加载失败时显示明确错误，但保留“打开原图”链接。
- 关闭查看器后焦点由原生 `<dialog>` 行为返回触发按钮。

## 状态与事件

查看器属于临时展示状态，不写入业务 `AppState`：

- 当前选中的 Meme 仍由 `AppState.selectedMeme` 管理。
- 事件委托在详情面板监听 `data-open-viewer`。
- `openImageViewer(meme)` 只负责填充和打开查看器。
- `closeImageViewer()` 只负责关闭查看器。
- 选择、编辑、删除或重新加载列表时，不改变已有业务请求流程。

## 错误与无障碍

- 卡片按钮保留包含标题的 `aria-label`。
- 详情预览按钮使用“查看《标题》原图”的可访问名称。
- 查看器通过 `aria-labelledby` 关联标题。
- 关闭按钮提供明确 `aria-label`。
- 图片替代文本使用 Meme 标题；装饰性渐变不进入可访问树。
- 现有图片 `error` 事件继续触发 `.is-broken` 占位状态，并扩展到查看器图片。

## 测试策略

Vitest/jsdom 增加以下行为测试：

- 卡片图片包含正确的 `width`、`height`，覆盖层包含标题和标签。
- 详情图片按钮具有正确原图 URL 和可访问名称。
- 点击详情图片打开查看器，并同步图片、标题和“打开原图”链接。
- 关闭按钮和背景点击关闭查看器。
- 查看器图片失败后再打开正常图片时，会清除错误状态并恢复正常显示。
- 点击图片、标题或内部按钮不会关闭查看器，只有点击 `<dialog>` 背景才关闭。
- 切换所选 Meme 后再次打开查看器时内容更新。
- 图片错误状态显示占位反馈。

CSS 多列的真实排版不由 jsdom 计算，因此使用浏览器手动验证：

- 横向、方形、纵向三种图片均完整显示。
- 宽、中、窄三种桌面窗口下列数自动变化。
- 卡片无裁切，悬停/聚焦覆盖层不改变布局高度。
- 详情面板与全屏查看器显示完整原图。

最终运行：

- `npm.cmd --prefix frontend run typecheck`
- `npm.cmd --prefix frontend test`
- `npm.cmd --prefix frontend run build`
- `.\.venv\Scripts\python.exe -m pytest -q`
