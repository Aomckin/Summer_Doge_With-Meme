# 模板参考原图与视觉匹配设计

## 目标

让 Meme Vault 的模板可选地绑定一张参考原图。AI 分析 Meme 时，带参考图的模板以视觉相似度为主要判断依据；没有参考图的模板继续通过名称与描述承载宽泛类别，例如“纯社交软件聊天截图”或“基于漫画截图的误解向创作”。

本期每个模板最多一张参考原图。

## 非目标

- 不做多参考图、多角度参考或模板相册。
- 不引入本地 CLIP、向量数据库或感知哈希匹配。
- 不让 AI 自动修改 Meme 的模板归类；现有人工确认步骤保留。
- 不改变标签、描述生成和既有 Meme 上传流程的语义。

## 数据与存储

`templates` 增加可空的参考图元数据：存储文件名、缩略图文件名、MIME 类型、文件大小、宽度、高度与 SHA-256 哈希。没有参考图时，所有这些字段为 `NULL`。

参考图使用与 Meme 图片相同的验证规则：只接受 Pillow 已识别的 JPEG、PNG、WEBP、GIF，限制最大文件大小，生成等比例 PNG 缩略图，并使用随机文件名。文件分别存储在 `data/template_images/` 与 `data/template_thumbnails/`，不与 Meme 图片目录混用。数据库只保存文件名，不保存绝对路径。

应用启动时为旧 SQLite 数据库逐项补齐新增列。新建数据库从 ORM 模型直接创建完整表结构。

删除模板时，先清除 Meme 与 AI 分析中的模板外键并提交数据库事务，提交成功后再删除参考图原文件和缩略图。替换参考图时，先安全写入新文件并提交新元数据，提交成功后才删除旧文件；任一数据库错误都会回滚并删除刚写入的新文件。

## HTTP 接口

保留现有 JSON 模板 CRUD：

- `GET /api/templates`
- `POST /api/templates`
- `GET /api/templates/{template_id}`
- `PATCH /api/templates/{template_id}`
- `DELETE /api/templates/{template_id}`

新增参考图资源接口：

- `POST /api/templates/{template_id}/reference-image`：multipart 表单字段 `file`，新建或替换唯一的参考图；返回更新后的模板。
- `DELETE /api/templates/{template_id}/reference-image`：移除参考图；返回 204。

`TemplateResponse` 增加 `reference_image_url`、`reference_thumbnail_url`、`reference_mime_type`、`reference_width` 与 `reference_height`。无图模板的这些响应字段为 `null`。静态文件挂载新增独立的模板原图与缩略图 URL 前缀，且只从受控存储目录读取。

## AI 视觉匹配与成本控制

AI 客户端的模板候选对象扩展为：模板 ID、名称、描述、参考图缩略图字节、MIME 类型与参考图哈希。Meme 服务读取有参考图模板的缩略图；无图模板只构造文字候选。

对有参考图的模板，AI 请求先给出一段包含模板 ID 的说明，再紧随对应缩略图。提示词要求以可复用画面结构判断：人物/主体、构图、分镜、物件关系及视觉布局；忽略二次创作时新增的字幕、聊天头像、聊天背景、边框和轻微裁切。文本描述不能覆盖与参考图相矛盾的视觉判断。

无参考图模板仍显示名称和描述，并被明确标记为“描述分类候选”。模型可用这些文字选择大类，但不得将其当作特定梗图原型的视觉证据。

每次请求至多携带 30 张有图模板的缩略图，以控制延迟与 token。候选顺序按模板 ID 固定；超过上限的有图模板不进入本次候选，无图模板仍可进入文字候选。API 响应必须仍只返回候选列表中的 `template_id` 或 `null`，服务层继续验证这一点。

对于 OpenAI Responses 协议，固定顺序的“系统匹配规则 + 视觉模板包”放在动态 Meme 输入之前，使用由候选模板 ID、参考图哈希和候选上限生成的稳定缓存键。模板图或模板集合变动时，键随之改变，旧前缀不会复用。请求启用提供方支持的提示词缓存，并记录响应中的缓存使用量（如提供方返回）。

对于 OpenAI 兼容 Chat Completions 协议，不假定提示词缓存能力：仍按同一顺序发送缩略图和动态 Meme，保证功能正确；未知缓存字段绝不发送给兼容供应商。参考图缩略图本身已减少首次请求的图像 token。

## 界面交互

模板管理对话框的创建和编辑表单增加可选的“参考原图”文件选择器。已有参考图时显示缩略图预览、视觉参考状态、替换操作和移除操作；没有参考图时显示“描述分类模板”状态及用途说明。

创建流程先保存模板的名称/描述，再上传选中的参考图。若第二步失败，模板仍存在，表单显示“模板已保存，但参考图上传失败”，并保留选择状态供用户重试。编辑流程可单独保存名称/描述、替换图片或移除图片。

模板列表显示缩略图或无图占位状态。AI 结果和 Meme 编辑/上传的模板选择控件继续只显示模板名称，不改变其人工确认体验。

## 错误处理

- 空文件、损坏图、超出大小、或不支持格式返回与现有 Meme 图片上传一致的校验错误。
- 模板不存在返回 404；删除不存在的参考图是明确的 404，而不是静默成功。
- 文件系统清理失败不回滚已提交的数据库操作；记录异常，避免把已完成的模板变更错误报告为失败。
- 读取某个参考图失败时，该模板不进入当次视觉候选，并继续让其名称/描述作为描述分类候选；分析不会因单个损坏文件中断。

## 测试与验收

后端测试覆盖：SQLite 迁移、模板参考图上传/替换/删除、静态 URL、路径边界、失败回滚和文件清理；视觉候选的缩略图读取、损坏文件降级、30 张上限、缓存键稳定性与模板变更失效；Responses 与 Chat Completions 的多图请求布局、无图文字候选和候选 ID 校验。

前端测试覆盖：模板响应类型与 API 封装、创建后上传、上传失败可重试、替换、移除、模板列表的预览/无图状态及既有模板选择控件兼容性。

验收时应能创建一个带 Drake 等原图的模板、上传其改编 Meme 并得到该模板建议；应能创建无图聊天截图大类模板并由 AI 作为文字分类候选；替换或删除原图后，预览与下一次 AI 请求均使用最新状态。
